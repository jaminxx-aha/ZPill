# 安全边界

NikonPill 在本机处理相机连接、媒体传输和 RAW 解码,不依赖项目自建服务端。
本文记录已经确认的安全边界、客户端不能单方面消除的风险,以及发布前必须
保持的配置约束。

## PTP/IP 与相机热点

尼康相机使用的 PTP/IP 接口是未经认证、未加密的 TCP 连接,默认端口
`15740`。App 无法在不修改相机固件的前提下给该协议增加 TLS 或可靠的端点
身份认证。

这意味着与相机处于同一网络、且能够访问该端口的设备,可能观察或干扰控制
指令与媒体传输。请遵循以下约束:

- 优先使用相机自己创建的热点,并为热点启用强密码。
- 不要通过不可信的公共 Wi-Fi 或共享局域网连接相机。
- 完成传输后关闭相机 Wi-Fi,避免长期暴露 PTP/IP 服务。
- 不要把端口可达或 TCP 连接成功误认为相机身份已经过认证。

## Wi-Fi 凭据

BLE 配对读出的相机热点 SSID 和密码只用于当前连接流程,不会写入项目配置
或持久化存储。日志不得记录明文密码或完整的 BLE 凭据载荷。

相机热点密码的界面可见性属于用户确认过的低风险产品取舍。截图或录屏仍可能
暴露该密码,分享画面时应避免包含凭据区域。

## RAW 与媒体解析

HarmonyOS 的 NEF/NRW 解码使用仓库内嵌的 LibRaw。Native 包装层会限制原始
数据和 RGBA 输出尺寸、设置 `512 MB` 原始数据内存上限,并把分配失败转换为
Promise reject,避免损坏文件直接终止进程。

媒体格式解析仍是攻击面较高的边界。升级 LibRaw 或其他原生解码库时必须:

- 同步上游安全修复,不能只修改版本注释。
- 重新构建 HarmonyOS Release HAP,确认所有原生源文件进入编译。
- 至少使用一份正常 RAW 和一份截断或损坏 RAW 做真机回归。

HarmonyOS 视频 LUT 导出还会校验容器报告的尺寸、像素数、轨道数、帧率、
声道、采样率和每个 Native Buffer 的实际容量。超出移动端边界或元数据互相
矛盾的文件会在进入解码、上色和混流前被拒绝。生成的临时视频使用 `0600`
权限。

## 构建与签名

私钥、证书、Profile 和密码不得进入 Git。当前约束如下:

- `ohos/build-profile.json5` 不保存本机签名配置。
- `ohos/signing/` 与被引用的证书材料由 `.gitignore` 排除。
- 密码只从 macOS Keychain 读取,不写入环境文件或签名 JSON。
- Hvigor 本地缓存使用 owner-only 权限,并可由下一次构建自动修复。
- CI 不接收发布签名材料,也不生成可分发的正式包。
- 发布检查会拒绝受版本控制的签名文件、`key.properties` 和 PEM 私钥。

详细操作见 [RELEASE.md](RELEASE.md)。

## 本地数据与日志

配对身份、设置、传输历史和诊断日志保存在 App 沙盒内。日志可能包含相机
名称、序列号、文件名、SSID 或设备标识,这些内容用于故障定位,但可能属于
隐私数据。公开提交日志前应先检查并删除不需要的设备信息。

`nikonpill-data` 属于设备本地状态,已从 Android 云备份/设备迁移和 iOS
iCloud Backup 中排除。换机后应重新配对相机,不能让旧配对身份随备份克隆到
另一台设备。用户媒体仍按系统备份设置保留。

## 发布前检查

- 使用正式证书和正式 Profile,不要发布调试签名的安装包。
- 按实际功能最小化定位、后台、蓝牙、Wi-Fi 和相册权限。
- 提供与权限和数据处理方式一致的隐私说明。
- 不在公开仓库、构建日志或 CI 配置中保存发布密钥。

## 报告问题

涉及凭据泄露、原生内存安全或可被远程触发的缺陷,请使用该代码托管平台的
私密安全报告入口,不要在公开 issue 中附带利用细节、真实密钥或用户媒体。
